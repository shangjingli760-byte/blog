## 2. 架构分层

### 2.1 表示层（Presentation Layer）
- **blog-web**: Next.js 服务端组件，SSG 预渲染
- **Hugo**: 静态 HTML 生成，含管理后台 SPA-like 架构

### 2.2 API 网关层
- Gin HTTP 框架，处理路由、中间件、请求响应

### 2.3 业务逻辑层（Service Layer）
- 封装核心业务规则和校验逻辑
- 事务管理、业务流程编排

### 2.4 数据访问层（Repository Layer）
- GORM ORM 封装
- 数据库 CRUD 操作抽象

### 2.5 数据存储层
- SQLite 嵌入式数据库
- 自动迁移表结构

## 3. 数据流

### 3.1 前台数据流向

```
构建阶段（SSG）:
  Next.js build → fetch /api/articles → blog-server → SQLite → 返回数据 → 生成静态 HTML

运行阶段:
  用户浏览器 → 加载静态 HTML → JS 加载 → fetch /api/articles/{slug}/comments → blog-server → SQLite → 返回评论列表
```

### 3.2 管理后台数据流向

```
浏览器 → 登录请求 → /api/admin/login → 验证用户名密码 → 返回 JWT token
浏览器 → 携带 token → /api/admin/articles → Auth Middleware → Handler → Service → Repository → SQLite
```

## 4. 认证与授权

### 4.1 认证机制
- JWT (JSON Web Token)
- Token 存储在 localStorage
- 有效期 24 小时

### 4.2 授权策略
- 公开 API：无需认证（文章列表、评论列表、提交评论）
- 管理 API：需 JWT Bearer Token（文章 CRUD、评论管理）

## 5. 部署架构

```
开发环境:
  blog-server: http://localhost:8080
  blog-web: http://localhost:3000 (开发服务器)
  Hugo: http://localhost:1313 (开发服务器)

生产环境:
  blog-web: 静态文件部署（Nginx/CDN/GitHub Pages）
  blog-server: 独立后端服务
  SQLite: 嵌入式数据库（同服务器）
```

## 6. 技术选型理由

| 类别 | 技术 | 选型理由 |
|------|------|----------|
| 后端语言 | Go | 高性能、并发能力强、部署简单 |
| Web 框架 | Gin | 轻量级、高性能、生态成熟 |
| ORM | GORM | Go 语言最流行的 ORM，自动迁移方便 |
| 数据库 | SQLite | 嵌入式、零配置、适合个人博客规模 |
| 认证 | JWT | 无状态、跨域友好、易于集成 |
| 前端框架 | Next.js | SSG/ISR 支持、App Router 现代化 |
| 样式 | Tailwind CSS | 原子化 CSS、开发效率高 |
| 静态生成 | Hugo | 极速构建、Markdown 支持好、主题丰富 |
